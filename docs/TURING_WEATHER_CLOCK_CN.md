# Turing 天气时钟模式（按 NexusMonitor 2.1.8 源码整理）

Turing 支持硬件监控、本地静态/文件夹壁纸和天气时钟。天气时钟沿用 Canvas → RGB565 → HardwareService 串口通道；同一时刻只能有一个串口写入者。横屏为 480×320，竖屏为 320×480，两者独立排版。

## 横屏布局

左侧天气图标和摘要、中左温度/体感/湿度，AQI 融入温度区域与右侧时间之间；右侧时间/日期/星期。下方显示风速/风向、降雨概率、PM2.5 等；左下为未来六小时（三列两行），右下为未来三天。

## 竖屏布局

独立重排时间、天气/温度、AQI、风雨指标、未来六小时网格和未来三天列表，不把横屏内容简单旋转或压缩。

## 天气数据与背景

WeatherService 读取当前天气、小时和逐日预报，并保留可用缓存。通用数据结构最多保存六条逐日预报；Turing 页面只显示前三天。六小时选择应严格晚于当前时刻。AQI 接口失败不应丢弃天气主体。代码包含 Open-Meteo、QWeather、WeatherAPI 与 OpenWeather 适配，实际设置以当前服务代码为准。

`public/turing-weather/` 包含 27 张 480×320 WebP（18 张晴天不同时间场景和 9 张多云、雾、雨、雷暴、雪/夜景）。`src/renderer/weather-scene.ts` 按天气代码和本地时间选图。更换场景先等待新图解码、重置帧基线并发送整帧；后续使用 16×8 差分与单写入者机制，不积压过时帧。

## 实机验收

检查横/竖屏文字、AQI、温度、日期、六小时与三天预报是否可读且不裁切；检查换图无残影/空白帧/并发写入；确认六小时严格在当前时刻之后、三天跳过今天。在真实 COM3 测量传输时间：480×320 RGB565 一帧为 307,200 字节，115200 baud、8N1 的裸数据理论下限约 26.7 秒，实际包括协议开销。拔插重连、睡眠恢复和长期稳定性必须单独实测。
