# Turing 天气时钟模式（2.0.4）

## 模式

Turing 页面现在有三个模式：硬件监控、静态壁纸、天气时钟。天气时钟使用与原屏幕相同的 Canvas → RGB565 → HardwareService 串口通道，不另开串口。

## 布局

### 横屏 480×320

- 左侧天气图标和描述。
- 中左当前温度、体感温度、湿度。
- AQI 放在温度区域与最右侧时间之间的留白处，不独占一行。
- 最右侧时间、日期和星期。
- 中间横线下显示风向/风速、降雨概率、PM2.5。
- 左下未来六小时，3 列 × 2 行；右下未来三天，三行纵向列表。

### 竖屏 320×480

重新排版时间、天气/温度、AQI、风雨指标、六小时网格和三天列表；不旋转或压缩横屏画面。

## 天气数据

`WeatherService.cs` 的 Open-Meteo 请求包括当前数据、24 小时小时数据和 4 个日历日期（今天加未来三天）。代码过滤掉今天，只将接下来三个日期序列化到 `dailyForecast`。小时序列继续只向 Turing 天气时钟显示接下来六个时段。空气质量接口是可选数据源；即使 AQI 接口超时或限流，也不能因此丢弃当前天气及预报。天气主接口失败会记录服务日志，并在没有可用缓存时由 Electron 主进程 45 秒后重试。

## 背景素材

`public/turing-weather/` 中包含 27 张 480×320 WebP：

- 晴天 18 张：清晨、上午、中午、下午、黄金时段、日落、夜间。
- 其他天气 9 张：多云、碎云、雾、细雨、雷暴、大雨、降雪、晴雪、月夜。

`src/renderer/weather-scene.ts` 根据 Open-Meteo weather code 和电脑本地时间段选择图片。选择结果在三小时块内稳定，并按日期作稳定变化，不会因硬件快照每秒刷新而抖动。

更换场景时，`TuringPage` 会先等待新图片解码，避免把旧图或空白图发送到屏幕；场景更换会重置帧基线并发送整帧。后续文本/时钟刷新继续使用现有 16×8 差分和单写入器，发送过程中只保留最新 pending 刷新，不堆积过时画面。

## 实机验收重点

- 横屏和竖屏的文字、AQI、温度、日期/星期、小时与日预报是否可读、是否有裁切；温度、时间与日期/星期应在 3.5 英寸实际观看距离下清晰。
- 更换天气或 3 小时时段背景时，完整画面是否正确且没有两次串口写入重叠。
- 六小时预报是否是接下来的六个时段；三天预报是否跳过今天。
- 在 COM3 实测整帧发送时间。480×320 RGB565 原始数据 307,200 字节，115200 baud 下 8N1 的理论下限约 26.7 秒，实际含协议开销可能更长。天气场景不会频繁按秒改变，但实机传输时间必须记录。
